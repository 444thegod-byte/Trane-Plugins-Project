## 教训（值得记住的）
- **「红得没有信息量 = 没红」。** 检查器崩了、pytest 找不到测试、环境问题 —— 这些对任何输入
  都成立，拿它们当「突变被抓住」的证据等于没证据。反向对照器现在一律：① 跑前先证明检查器
  在干净源码上是绿的；② 只认 `✗` / `FAILED`，异常退出明确判为「不算抓住」。
- **改名/重构时，锚点和节点名要跟着改。** 失效的锚点有两种下场：要么在 `assert n == 1` 上崩掉
  （至少响），要么像 pytest 节点名那样**静默地**把对照变成空话。
- **v0.33 施工纪律**：删功能 = 删断言 = 删反向对照锚点，三件事一起做。

## 先收尾任务 #31：数值列宽从「按字符数估」改成「实测」
两条前提**都不成立**（`kValueW = 0.60` 是平均值不是上界，实测最宽字符 `M` = 8.314px
而模型给每个字符 7.2px；41 个控件里 10 个在量程两端的串比默认值长）。
修法不是加余量，是**结构性地消除模型**：`Extents::vmaxW` 用
`GlyphArrangement::getStringWidth` 实测，列宽**正好**等于最宽串。
- 实测 `value_w` 从 43.2 → **38.048px**（= `+10.0DB`），轨道从 162.780 → **167.932px**（+5.15px 实用长度）。
- 十个数字确实等宽（全 5.6840px，AbletonSans Medium 是比例字体）；`i` 2.2040 ≠ `M` 8.3140。
- 删掉 `kValueW`，注释里写清两条失效前提并警告**别再把它加回来**。

## 旋钮（12 个）：判据要能一句话说完
判据 = **带物理单位的（ms/Hz/x/gr·s⁻¹）→ 旋钮；无量纲 0..1 与 dB → 条形**。
- 第一稿 14 个，含 `sweep_reso` / `space_size`（都是 0..1）—— 退回条形。
  **判据一旦不能一句话说完，下一个人加参数就只能靠猜。判据的价值在于可判，不在于好用。**
- **同一模块内旋钮必须连成一段**（第一稿 GRAIN 第 5 行、SWEEP 第 3 行各有一个孤零零的旋钮，
  渲染出来看图才发现）。为此改了两处行序：`grain_rate` 前移到 density 之后（三个都是
  "粒子在时间上的尺度"，依据 `core/GrainCloud.h:25`）；`sweep_center` 前移到 rate 之后
  （依据 `core/RandomSweep.h:29–33`）。
- **拖拽一处未动**：它是纵向位移映射（`pressValue_ + dy/kDragSpan`），与控件长什么样无关。

## 「切割成块」只剩留白这一条路

## 撞出来的真问题：旋钮直径与行距是两个独立决定
直径跟字号走（`kFsName × 2.2` = 24.2px），行距跟栏走 —— 两者会不会撞车**只有放在一起算才看得见**。

# v0.35 —— 按模块分配形态 + 每个模块一个框 + 换成开源字体

用户原话：「我说的旋钮不是把某一参数变为旋钮，而是一整个模块里的参数，比如 GRAIN
适合旋钮表示的话，那就 GRAIN 的参数全部都用旋钮来表示，同时这是一个单独的模块，
要做成一部分框起来，具体的感觉/参照可以去参考 VCV Rack 和模块效果器的感觉，
我要的是这样的，只不过是变为 Lux Cache 感觉版本的。」

## 一、形态从"逐参数"改成"按模块"
`kKnobIds[]` → `kKnobModules[]`（5 个）。`isKnob(控件) = 它所属的模块在清单里`，
中间多一跳"控件 → 模块 → 清单"。选中的是**前五级**（freeze/grain/stutter/comb/tape），
后五级（ruin/sweep/delay/space/out）保持条形 + 一个分段块。
- 判据一句话：**这个模块是"调到目标"（速率/时间/音高，靠耳朵找）还是"设个量"（混合/驱动/输出）**。
  v0.34 那条"带物理单位 → 旋钮"的判据**作废**：GRAIN 的参数大半是无量纲的，
  按旧判据它不该有旋钮，而它显然是"调"出来的模块。
- **同模块内一致性成了构造保证**：没法表达"这一行不一样"。于是 v0.34 那条
  「同一模块内旋钮必须连成一段」的断言**删掉**（它再也不可能失败，留着会让下一个人
  在别处动到它时选择"调松"而不是"查"）。为此 v0.34 改过的两处行序（`grain_rate`、
  `sweep_center` 前移）也不再需要 —— 但**没回退**，因为回退是又一次无谓的改动。
- **新增一条禁令**：含 `Fmt::Choice` 的模块不许进旋钮清单（分段块没有环，
  进了会让检查器去找不存在的环 → **假报红**）。

## 二、分组从"留白"改成"框"（用户此前否掉过边框，这次是用户点名要的）
`kSectionGapMult` 删掉。每模块一个容器：块底 `kInk @ 0.055` + 发丝框线 `@ 0.11`，
圆角 10，`kBlockPadX/Y = 14/12`，`kBlockGap = 15`。
- 只取 VCV Rack / 模块效果器的**"模块是独立面板"这一层**，拟物一概不要，
  转译成 Lux Cache 的语言：**无阴影、无彩色、无渐变、无斜面**，两层墨而已。
- 缝宽用**绝对 px** 是可以的（容器自带边界）—— v0.34 那条"必须是行距的倍数"
  只在"留白是唯一分组线索"时成立。
- **内缩不是免费的**：`padX` 吃掉内容宽。所有"三段宽填满一栏"的判据基准要改成
  `栏宽 − 2×padX`，否则报 28px 的错，看起来像排版歪了。实测 41 行报红 14.50/15.00px。
- 框线是**压在块底上**的（`drawBlock` 先填充再描边，线内缩 0.5px 后整根落在填充区里），
  所以合成色是 `0.11` 的墨压 `0.055` 的块底 = **#262627(38,38,39)**，不是压纯黑的 #1A1A1B。

## 三、字体：取证 → 量化选型 → 打包
- **取证**：Lux Cache 站上取 woff2，`fontTools` 读 `name` 表 → **Suisse Neue / Suisse Int'l**，
  商业授权，**不可打包**。
- **选型**：候选 Inter / IBM Plex Sans / Source Sans 3 / Archivo / Public Sans。
  两条量化判据：**竖干宽度**（`H` 在 25%/75% 高度取横截线 —— **不能取中线**，
  那是横杠的厚度）+ **软 IoU 骨架比对**（**先按字重对齐再比**）。
  实测 Inter 0.94 对第二名 0.86，定 Inter（OFL-1.1）。
- **两个在插件里真会坏的**：① **等宽数字** —— Inter 默认比例数字，等宽的是独立的
  `.tf` 字形，要**remap cmap**（不能指望 JUCE 去应用 `tnum` feature）；
  ② **字形覆盖** —— 面板会渲染的字符清单必须从控件表算出来，逐个问字体有没有。
- **打包**：`BinaryData` + `createSystemTypefaceFor`，**不许运行时查系统字体**
  （会静默降级成用户装的那个，画面照样有东西，看不出坏）。
- **判据**：换字体**只改文字墨迹、不改任何几何** → 唯一能抓到它的是 dump 的
  `font_ui` / `font_data`（字体自述名 + 实测探针宽度），测试用 fontTools 从 `.ttf`
  的 `hmtx` 独立复算。名字证明"是打包那份"，宽度证明"是**对的那个字重**"
  （两个字面的 family 名一样，光看名字分不出 Regular / SemiBold）。
- 原来那条「字体来自用户机器上的 Ableton 安装」的断言**整条反向改写**成
  「不许再出现 Ableton 路径 + 必须来自打包数据」—— 功能反了，断言的方向跟着反。

- **按模块分配让"一致性"从断言变成构造。** 删掉一条再也不可能失败的断言，

- **手册里要写"为什么"**：停转为什么必须同时停写头、抖动为什么不能乘在速率上、
  `fold` 为什么在 `crush` 之前、扫频为什么用随机而不是 LFO。
  这些理由都在 core/*.h 的头部注释里，抄过来比重新想准确。
- 一条**用户不知道的事**必须写明：**出厂状态不是全干** ——
  RUIN 与 SPACE **没有开关**，出厂就带 drive 0.35 与 space mix 0.55。

## 推送这一段（踩到两个坑）

1. **`git push` 被 `! [rejected] (fetch first)` 挡下** —— 远端有本地没有的提交：
   用户在 **GitHub 网页上**改了 README（`d03380b Update README.md`，
   把"目标是做出 S280F、Fitness 那类…"那句删掉了）。
   处理：`git fetch` → `git show` 看清 → `git rebase origin/main`（保持线性）。
   **没有用 `--force`。**
2. **变基不会提示"你把用户删掉的东西加回去了"** ——
   我在 README 新写的那行里有 `Lux Cache / petri`，和被删掉的那句是同一类东西。
   这不是冲突（是新增内容），git 一声不响。
   自己拿被删的词搜了一遍新文件才发现，改成中性描述。
   **公开仓库里"引用了谁"是用户的决定。**

## 环境

- 本机 **没有任何 GitHub 凭据**：`gh` 没装、`~/.ssh` 不存在、
  钥匙串里没有 github.com 条目。
- 走 skill `github-verified-publish` 的路子：从官方 release 下**单文件** gh 到
  `/tmp/gh_cli`，`GH_CONFIG_DIR=/tmp/gh_config`。
  **`/tmp/gh_config/hosts.yml` 里已经有上次的授权**（`gh auth status` 直接 ✓，
  scope 含 `repo`）—— 所以**没有再让用户输一遍设备码**。
- 推送必须显式挂凭据助手，否则 git 去碰钥匙串会挂住：
  `git -c credential.helper= -c credential.helper='!/tmp/gh_cli/gh_2.101.0_macOS_arm64/bin/gh auth git-credential' push origin main`
- 34 MB 的推送在这台机器上要十几分钟（`git send-pack` 长跑，0% CPU 是正常的，
  用 `lsof -nP -iTCP -sTCP:ESTABLISHED | grep git` 确认连接真的在传）。

## 推送结果（成功）与第三个坑

**第一次推送失败**，报：

```
error: RPC failed; curl 16 Error in the HTTP2 framing layer
send-pack: unexpected disconnect while reading sideband packet
```

看着像"网络慢"，实际是**协议层断在一次都没传完**（远端 HEAD 还是老的）。
34 MB 的 pack 走 HTTP/2 在代理后面会断。**加 `-c http.version=HTTP/1.1` 就好了**，
第二次 12 分钟推完，日志里 `Writing objects: … 43.07 MiB/s` —— 速度根本不慢。

教训：**"十分钟没输出"不等于"在传"**。要 `--progress` 重定向到文件看百分比，
或者直接查远端 HEAD 有没有动。

**推送后核验（三层全过）**：
1. 提交哈希：本地 == 远端 == `2d675bb`。
2. 逐文件 blob：**222 个文件全部逐一致**。
   （第一次 diff 报假差异 —— 本地 `git ls-tree` 默认把非 ASCII 路径转义成
   `"docs/\344\275\277…"`，API 返回原样 UTF-8。加 `-c core.quotepath=false` 才对。
   判据：**先看两边行数相等**，相等就是格式问题不是内容问题。）
3. 关键文件独立 sha256（绕开 git 直接下 raw）：使用说明 / logo 容器 /
   打包字体 / 两张 v0.36 出图，5/5 一致。

远端：`d03380b..2d675bb  main -> main`。

## 沉淀到技能

`github-verified-publish`（用户级，agent_created）补了三节：
- **授权前先看 `gh auth status`** —— `/tmp/gh_config/hosts.yml` 是持久的，
  有现成授权就别让用户重走设备码。
- **推已存在的仓库要先 `fetch`**，看清网页上的改动再变基；
  **变基不会提示"你把用户删掉的东西加回去了"**，要自己拿被删的词搜一遍新文件。
- **大推送加 `http.version=HTTP/1.1`**；核验用 `core.quotepath=false`。
