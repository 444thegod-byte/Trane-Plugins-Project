## 10:10 · UI v0.25 —— 模块成块 + 上下完全对齐（小绪两张标注图）

小绪 09:41 / 09:42 两张标注图，两条要求：
1. **对齐**：「上下完全对齐，要按最高最低对齐」—— 所有块的上边、下边跨列相等。
2. **模块化**：「要分成一块一块的」—— 每个模块要有可见的块边界。
   附注「我画的不齐，只是给你参考」= 标注是示意，不是精确稿。

### 落地方案（`vst/tools/render_ui_dark_panel.py` v0.24 → v0.25）
- 新增 `block_frame()`：极淡填充 `BLOCK_FILL_A = 0.024` + 1px 描边，带 `class="blk"` 供断言识别。
  描边亮度跟模块开关走：亮 `0.34 + 0.14×breath`，灭 `0.16`。
- 新增 `content_span(m)`：块区 = `ROWS_TOP` 到 `ROWS_TOP + avail_h`（578px）。
- `module_layout`（MODULE 模式）：**每列一个块，块高 = 整列内容区高度**。短模块块内下方留空。
- `all_layout`（ALL 模式）：每块按内容高，**只有每列最后一块补到内容区底** —— 否则各列
  行数不同（17/13/19）底边参差。补的那一截就是块内留空，和 MODULE 模式同一个道理。
- 块容器**必须先于内容画**（填充半透明，盖在字上会压灰）。
- 删掉 `column_block` 的 `sep` 参数（发丝分隔线被块容器取代）。

### 为什么不做「把行距拉开填满块」那一版
MODULE×4 下 GRAIN 行距 55.3px，STUTTER 要拉到 107.6px —— 相邻两列差一倍，
而且会毁掉行网格。**块内留空**比**行距不均**好看，也更诚实。

### 关键新发现（都已变成断言/规则）
- **加了块填充 = 给块内每一处文字换了底色。** `backdrops()` 多出一档 `"block"`，
  轨道也改成从 block 叠上去（不是从 bg）。最紧的一处 5.11 → **4.89:1**，仍过线。
- **登记表与 SVG 必须同序**。`panel()` 原来是「先算 body、再在 f-string 里算 tabs/heading」，
  于是 log 顺序（tree→body→tabs→heading）与文档顺序（tree→tabs→heading→body）错开，
  按位置对账全错。改成**按文档顺序依次生成**再拼接。
- **新增第三把尺子**：文字**落在块内还是块外**（几何判定）必须与登记的底色一致。
  只对 alpha 对账挡不住「块内文字仍按面板底算」—— 两边数值一模一样。
  反向对照实测：`文字 (422,161) 在块里，却登记成 'bg'` ✓
- **容差不能比取整误差还小**。块宽断言写成 `< 0.05`，而 SVG 只留 1 位小数（误差 0.05），
  于是报出**撒谎的现场**「块宽 238.8 ≠ 列宽 238.8」。改成 0.06（高差 0.11）并把
  **差值**打进消息里，永远不会再出现 `X ≠ X`。
- **命中数下限**：块提取正则匹配不到 → 几何断言会把每处块内文字都判成"不在块里"，
  报出的现场是误导的。先在 `check_contrast` 里 `assert frames, "一个块容器都没量到"`。

### 验证
- 自检全绿。最紧对比度 **4.89:1**（`ALL/1·b0.00` α=0.52 压轨道底 `#2D2E2E`）。

## 10:2x · UI v0.26 —— 内边距 + "末行对齐"（小绪两张标注图）

小绪 09:4x 两条：
1. **「文字和边都挤成那样了，直接给我把边也留一部分空间，不要这样一直挤空间，
   要求给边也加上一模一样的间距」** —— 块的**四边**都要有和行内一样的间距。
2. **「我的对齐是 GRAIN MIX 和 STUTTER MIX 这样对齐，其他均匀分布」** —— 对齐的是
   **每列的末行文字**（`* MIX` 那一类），组内其余各行均匀分布。

### 落地方案（v0.25 → v0.26）
- 新增 `BLOCK_UP = 19.4` / `BLOCK_DOWN = 12.6`（= 内边距 + 字高/降部），块内首行/末行
  到块边的距离都等于 GAP。
- `columns_for()` 新增 `row_box`（行框高）参数，`pitch` 由它推。
- `module_layout` / `all_layout` 改为**逐列解 pitch**：`pitch = [avail_h − blocks·(UP+DOWN)·S]
  / (rows − 1)`。

### 结果：**这是一个真 bug，而且自检是绿的**
小绪 09:5x 一句 **「这也没对齐啊，傻逼吧」** 点破 —— GRAIN MIX 比 COMB MIX 低 39px。

**根因**：v0.26 对齐的是**行框的底边**，不是**文字**。行框不可见，文字是"居中放进行框"的；
行框高逐列差 2.5 倍（GRAIN 53.1px / COMB 132.0px），居中之后文字差
`(132.0−53.1)/2 ≈ 39.5px`。
**而自检当时是绿的 —— 因为它量的也是行框底边。**

> **教训（本会话最重要的一条）：断言公式写对了还不够，取样点本身可能是盲区。**
> **量的东西必须是肉眼能看见的东西。**

## 10:3x–10:4x · UI v0.28 —— 去边框 + Apple 系统化（本会话主体）

小绪 09:5x 的原话（**方向性大改**）：
> 「算了我不要模块化的边框了，你做的太丑了，直接按照目前市面上最高级的 UI 来做！！！！
> 去找 Apple 的 UI 设计，然后直接学习，然后直接在基础上给我优化，
> 不管是动线还是交互效果，还是排版，按照 Apple 做系统/软件的思路来帮我优化」

拆成三条落地。

### ① 去掉模块化的边框
删 `block_frame()`（描边 + 填充）、`module_gap()`、`block_pad()`。
分组回到 HIG · Layout 的**第一**手段 —— **留白**。HIG 原文给了三种：
`negative space, container shapes, or separator lines`；小绪否了后两种。
留白能分组的前提是**组间空档明显大于组内**，必须两个量级：
- `GAP = 8`（名称─轨道─数值）· `COL_GAP = 28`（列间）· `SECTION_GAP_MULT = 2.5`（组间 = 行距 × 2.5）。
- 自检硬断言：**任何 `<rect>` 都不许带 `stroke=`**（发丝线是 `<line>`，不受影响）。

### ② 去学 Apple 的规范（有据可查，没编数字）
用 WebFetch 抓了 developer.apple.com 的 Layout / Typography / Color / Motion 四页，
再用 WebSearch 补齐**深色模式语义色的真值**（`noahgilmore.com` 的实测表）。
- **配色**换成 Apple 语义色：`systemBackground #000000` · `secondarySystemBackground #1C1C1E` ·
  `systemFill rgba(120,120,128,.36)` · `separator rgba(84,84,88,.60)` · `systemGray2 #636366`；
  文字基色 **`#EBEBF5`（微冷，不是纯白）**。
  **关键发现：Apple 的层级机制只有两套 —— 面的明度 + 文字四级不透明度 ——
  没有"边框"这一层。** 正好接上第 ① 条。
- **字号**抄 Apple macOS 内置文字样式阶梯：`FS_TITLE/VALUE/NAME = 13 / 12 / 11`，
  字重 600 / 500 / 400，**没有细字重**（HIG 明确"避免 Light"）。
  放不下时**整体等比缩**（`scale_fit`），**不许某一档单独变**。硬下限 `FS_MIN = 10`。
- **两处刻意偏离 Apple，都写了理由**：① `tertiaryLabel(0.30)` / `quaternaryLabel(0.18)`
  在黑底上只有 **2.23:1 / 1.55:1**，**过不了 WCAG AA 4.5:1** → 文字只用前两级
  （1.00 / 0.60），关闭态用 **`A_OFF = 0.56`（4.85:1）**，Apple 的 0.30 只给非文字用；
  ② 分段控件保留**直角**（小绪早先明确"不要圆角按钮"）。

### ③ 排版：层级反转 + 填充式控件
- **参数名降一级、数值升一级**：名称 = Caption 1（11pt / Regular / 0.60），
  数值 = Callout（12pt / Medium / 1.00）—— 插件里数值才是用户要读的。
- 分段控件改 **Apple 填充式**：底 `tertiarySystemFill` + 选中块 `systemGray2`，
  **去掉边框与分格发丝线**。模块关着时**不画选中块**（Apple 的禁用控件是"摊平"的，不是"变暗"的）。
- 开关方块去掉描边：关 = `systemFill` 实心块，开 = 主内容色实心块。

### 自检：这一轮抓到三个**自检自身的缺陷**
1. **对比度复算用纯白合成 → 算高对比度。** 文字实际是 `#EBEBF5`，用 `(255,255,255)` 合成时
   分段选中标签退回 0.56 仍"过线"（按 #EBEBF5 算只有 2.7:1）→ 突变漏网。
   修：`check_contrast` 改用 `INK_RGB`。
2. **几何尺子只查单向。** 只查"登记成 `seg` 的文字必须在分段矩形里"，
   挡不住"把 `seg` 写成 `bg`"（bg 更亮、对比度反而更高，两边一起错没人管）。修：反向也查。
3. **分组空档的动态比值被稀释。** `BLOCK_UP+BLOCK_DOWN` 那 32px 把 `max/min` 抬到 2.37，
   倍数降到 1.2 仍看着"通过"。修：加**静态**断言 `SECTION_GAP_MULT >= 2.0`（设计值直接卡住）。

### 反向对照：19/19 + 1 对照组（修完三处漏网后）
过程中又暴露**两个新的空转模式**：
- **覆盖漏洞**：`sweep_mode` 是全工程唯一的 Choice，而 `sweep ∉ LIT` 也不在 `SELECTED` 里
  → `param_row()` 里 `if i == pos and active:` 那条分支**从未执行**，改坏它的 α 一个断言都不响。
  修：自检里临时把 sweep 点亮，并用**差分**断言 `seg_on` 计数必须变多（实测 1 → 2）。
- **突变原文落在注释里**：`check_contrast_mutations.py` 用 `.replace(old, new, 1)` 换的是
  **第一次出现**；文件头 docstring 里写了句 `SECTION_GAP_MULT = 2.5` → 突变改的是注释、
  常量纹丝不动、被记成"漏网"。修：新增 `locate()`，用 `tokenize` 标出注释与**独占逻辑行的
  字符串**（docstring），只改代码区；找不到就报错。**护栏本身也配了自检**
  （注释 / 文件头 docstring / 函数 docstring 必须拒；真常量 / f-string 里的代码必须放行）。

## 11:0x · UI v0.29 —— 交互状态（小绪只说"继续"，按 HIG 能站住的那一档做）

09:5x 那句总纲里点了「不管是动线还是交互效果，还是排版」。v0.28 只做了排版，
这一轮补**交互效果**。他没指定范围，所以选了 HIG 能站住的一档（A+B）：
**状态可见性做全，过渡只给低频动作，拖参数不加动效。**

### 核心规则：**状态只改颜色，不改几何**
四态 `idle / hover / press / focus`。断言直接对四张 SVG 逐元素比对：
所有文字的 `(x,y)` 与所有矩形/轨道的 `(x,y,w,h)` 必须**逐字节相同**。

为什么这条比"好不好看"重要：
- 状态一变就重排 → 鼠标扫过去"跳一下"；
- **更要命的是**：上面那一大段排版断言（末行对齐、列距、分组空档）会**全部失效** ——
  状态成了排版的一个隐藏输入。

实现上靠 `class="st"`（行底）与 `class="fr"`（聚焦环）两个标记把它们排除出几何比对。
**用 class 而不是"看起来像"** —— 靠颜色或坐标猜，改一次绘制就失准。

### 四个状态
| 态 | 画什么 |
|---|---|
| idle | 常态 |
| hover | 整行一层 `INK @ 0.06` 的墨 + 参数名 `0.60 → 0.80` |
| press | 墨层 `0.12`（= hover 的 2 倍）+ 参数名 → `1.00` |
| focus | 轨道外一圈 **3px 强调色环**，与控制体留 2px 空隙 |

- 强度必须**单调**且 press ≥ 2× hover（不然"按下"和"悬停"分不清）。断言卡住。
- **强调色 = `#0A84FF`（macOS 深色 systemBlue，也是 `keyboardFocusIndicatorColor` 默认值）**，
  是本面板**唯一**允许出现的彩色，且**只准出现在聚焦态** —— 断言
  `(ACCENT in svg) == (state == "focus")`。
- 行底会**改变文字的底色**，所以 `backdrops()` 加了 `hover / press / seg_hover / seg_press`
  四档（`tertiarySystemFill` 是半透明的 α=0.24，行底会透上来）。**登记表必须跟着换**，
  否则对比度是拿面板底算的虚数。

### 动效规格（HIG · Motion）
| 动作 | 时长 | 依据 |
|---|---|---|
| 悬停 / 按下反馈 | **0.12 s** | `Feedback motion … should be brief and precise` |
| 模块开关 / 模式切换（低频） | **0.20 s** | 低频动作给点过渡，帮人确认状态变了 |
| **拖参数（高频）** | **0.00 s** | `generally avoid adding motion to UI interactions that occur frequently` |
| 打开「减弱动态效果」 | **× 0.0（全部归零）** | `make motion optional` / `let people cancel motion` |

曲线 `cubic-bezier(0.2,0,0,1)`（减速）。`MOTION_MAX = 0.30` 是 brief 的上限。
**Reduce Motion 必须精确等于 0** —— 写成 0.05 之类的"小一点"等于没关掉，断言卡住。

### 自检里又踩到的两个坑
1. **断言写在循环体里 → 分支永远不执行。** `assert_no_frames()` 一开始写在
   `for (mode, n), svg in svgs.items()` 里，而那个循环只跑 idle 面板 ——
   于是 `state == "focus"` 那一支永远不执行，聚焦环根本没验过。
   修：抽成共享函数，常态五张 + 四个状态**各调一次**。
2. **护栏判据写太严 → 误伤合法突变。** `locate()` 一开始是"碰到注释就算"，
   结果一条带**行尾注释**的代码行（`th = track_h(col)  # 同上…`）被整条判成注释，
   护栏自己把合法突变拦下来了。修：判据改成"**整段**都被注释/文档字符串盖住"，
   只要开头落在代码上就放行。并补了一条护栏自检用例。
   顺带把报错分成两种：「整段都在注释里」vs「源码里根本找不到（锚点过期）」——
   这一轮就靠后者抓到两处过期锚点（`log_text(a_name, "seg")`、`param_row(...)`）。

- 自检全绿，新增打印：

### 先量，再改：动线的三条事实
1. `core/TraneEngine.cpp::process()` 的顺序 =
   `freeze → grain → stutter → comb → tape → ruin → sweep → delay → space → limiter`。
   证据：`grep -n '_\.process' core/TraneEngine.cpp`（第 94–118 行）+ `TraneEngine.h` 头注释。
2. `panel_probe --dump-geometry` 的十个质点 **y 单调不减，恰好就是这个顺序**：
   102 → 199.973 → 199.973 → 395.919 → 395.919 → 493.892 → 591.865 → 591.865 → 689.838 → 885.784。
   **→ 树在几何上早就是信号流了，只是没画出来。** 十个点落 7 层（三对同层）。
3. `ALL_LANES` 展平 = `["freeze","grain","stutter","comb","tape","ruin","sweep","delay","space","out"]`
   = 上面那条链。**检查器的阅读顺序也早就对上了。**

结论：**缺的只有"线"。** 而 `PATHS` 那 22 条是生命之树的**标准连线**（相邻质点两两相连），
不表流向 —— 实测它相对信号链**命中 8 条、缺 1 条**（缺的是 `stutter → comb`）。

### 做法：树上分三层，用**质地**分层
- ① **骨架** = `PATHS` 22 条，**点线**（`stroke-dasharray`），`GRID_OP = 0.13` / `TRUNK_OP = 0.22`。
- ② **信号** = `SIGNAL_PATH` 9 条，**实线 + 沿线渐变**（上游淡 0.34 → 下游亮 0.85），
  `SIG_W = 1.6`。**不画箭头** —— 渐变本身就说明方向，不会在暗底上留刺眼的形状。
- 信号层**独立于 PATHS**（因为 `stutter → comb` 不在那 22 条里），
  所以生命之树「一条不多一条不少」的设定**原样保住**。
- `TRUNK`（中柱 keter-tiferet-yesod-malkuth）从"强调"降级为骨架里略重的一档 ——
  它和新信号层抢强调会互相打架。

### 这一轮量出来的两个新坑
1. **点线太省墨，不透明度要给到你以为的两倍。** 第一版 `GRID_OP = 0.07`，
   渲染成 PNG 后挖掉节点圆盘、取线上像素峰值 —— 只有 **25/255**，肉眼根本看不见。
   原因：直径 0.9px 的点每 8.8px 才落一个，覆盖率不到 1%。

## 17:35 · **MODULE 点不开的根因找到了**（小绪反馈了两轮的 Bug）

## 18:05 · 「参数条指针是假的」—— 量出来是真的假

### 小绪的反馈
> 「现在的参数条指针是假的，我需要你做成真的」

### 先量，再改
给 `panel_probe` 加了 `--set <paramId>=<真值>`（按真值设，不用手算归一化），
然后把 `grain_spray` 渲成 0.0 / 0.5 / 1.0 三张 1:1 PNG，直接读像素剖面。

**量出来的事实**：

| 元素 | 值=0.0 | 值=1.0 | 结论 |
|---|---|---|---|
| 填充条 | x 527..530 | x 527..682 | **会动**（轨道 527..682，宽 155） |
| 一条贯穿竖线 | x = 550 | x = 550 | **不动** |

那条竖线画在 `defaultNormalised()`（出厂值）上，而且 **15px 高 —— 是轨道（4px）的
4.4 倍**。它是整行里最像指针的东西，而它永远不动。真正跟着值走的填充条只改颜色、
不加把手，反而像背景。

**所以"指针是假的"是真的**：小绪看到的"指针"是出厂值参照线。

### 改法
不是"再画一根会动的线"，而是**先把误会拆掉**：

1. 出厂值刻度挪到**轨道下面**，只留 2px 高 —— 尺子上的刻度没人会当指针用。
   位置从 `mid + th*0.5 + 1.5` 改成 `mid + th*1.6`：指针下摆到 `mid + th`，
   原来的位置两者只差 **0.45px，会黏成一根更长的指针**（像素 diff 里直接看出来了）。
2. 加**真指针**：`{px, mid - th, 1px, th*2}`，`px = tx + clamp(0.5, trackW-1.5, trackW*nv)`。
   - 用**真值位置**、不加最小宽度 —— 加了的话指针在 0 处会离开轨道左端，"零"就不是零了。
   - 两端内缩，保证 1px 线整根都在轨道里。
3. 填充条的 alpha 从 0.80+0.20·breath 降到 0.62+0.18·breath，把"亮度"让给指针。

### 验证（三张图的指针 x）
| 值 | 指针 x | 参照刻度 x |
|---|---|---|
| 0.0 | 527–528 | 550 |
| 0.5 | 604–605 | 550 |
| 1.0 | 680–681 | 550 |

0.5 → 604 = 527 + 77.5 ✓ 位置精确。

四条断言：① 指针随值单调右移且落在真值比例上；② 指针**伸出轨道**（不然只是填充的边）；
③ 轨道下方像素在值变化时**一个都不许变**（刻度必须钉死）；④ 刻度与指针之间**必须有空隙**。

## 门禁 gate5 退出码 1 —— 根因是「绝对毫秒判据被噪声打红」（v0.32.5）

### 症状
`./run_tests.sh` 退出码 1，唯一红的一条：

    ✗ bg: 冷重烤在预算内  69.37 ms（门槛 60；实测 28.7 ms @2× 参数区、3000×3000 源图）

**与 v0.32.4 的指针改动无关** —— 那条改的是 `drawParamRow`，冷重烤走的是 `bakeBackdrop`。

### 定位：这是噪声，不是退化
同机器、同二进制、同一条命令连跑五次：

    26.91 / 26.15 / 27.21 / 27.52 / **71.32** ms

第五次连热路径一起膨胀（1.65 → 5.27 ms）—— **整台机器被抢了**，不是代码变慢。

根因：探针**只量一次**冷重烤，而这是整份门禁里唯一的绝对毫秒判据。
单次采样把"机器忙"读成"代码慢"，是最坏的一种判据 —— 既误报，又会被噪声逼着把门槛往上放。

### 修法：改**测量方法**，不是改门槛
`panel_probe` 加 `--cold-reps`（默认 **5**），报**最小值**，最大值一并打出来：

    背景重烤 21.20 ms  (冷：…；5 次取最小，最大 25.15 ms)

取最小**不是放宽门槛**：一次确定的运算，成本就是它**能跑到的最快值**，噪声只会让它更慢；
真变慢了最小值也会跟着上去。实测极差 **173% → 1.9%**（21.10–21.50 ms，六次）。

**每个 rep 必须是真冷**：`bdScaled` 的失效条件是 `bdImage/bdWhere/bdW/bdH`，
**明暗度不在其中**（那正是它便宜的原因）。所以：
- 有背景图 → 在两个**内容相同、缓冲不同**的 Image 之间来回换（`getPixelData()` 指针不同 → 骗过缓存）；
- 没背景图 → region 为空、缩放本来就不跑，改用明暗度顶开 `bakedBright`，
  否则 rep 2 起全是缓存命中，报 **0 ms**，判据当场作废。

### 门槛**维持 60，没有收紧**
8 个进程同时抢 CPU 时，最小值也会被抬到 **30.2–58.3 ms**（最大 274 ms）——
贴着 60 了。取最小压掉一大截噪声，但压不到零。
拿一台被抢得很凶的机器去卡一条一次性动作的绝对毫秒数，本身就是错的问题。
（真正的回归探测靠**相对判据**：8 份负载下热/冷比值 0.048–0.119，和空载 0.07 一样稳 ——
机器快慢在分子分母上约掉了。）

### 反向对照：**6/6**（新增 M6）
M4 与 M6 的分工值得记，因为它们是**两条不同的判据**，缺一不可：

| 突变 | 冷路径 | 热路径 | 被谁抓住 |
|---|---|---|---|
| **M4** 拆掉 `bdScaled` 缓存判据 | 21 ms（**绝对门槛照样绿**） | 塌成 22.68 ms | **相对判据**：比值 0.91 > 0.5 |
| **M6** 源图缩放做 4 遍 | 76.03 ms | 1.4 ms（比值照样绿） | **绝对预算**：76 > 60 |

只留绝对门槛会漏掉 M4；只留比值会漏掉 M6。
**M6 是专为"改成取最小"配的对照** —— 取最小会不会把真退化也一起压掉？76 ms 就是回答：压不掉。

`check_backdrop_mutations.py` 里 M6 已固化（原来 5 条，现在 6 条）。
