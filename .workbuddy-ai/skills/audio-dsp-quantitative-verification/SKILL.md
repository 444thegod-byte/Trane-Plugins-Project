# 量化验证音频 DSP

**核心原则：听不见的东西不许猜，去量。** 每一条"这个模块能用"的结论背后必须有一个数字，
而且那个数字必须能区分"对了"和"错了"。

## 一、三段式流程

```
1. 写探针（离线渲染）  →  2. 量出基准值  →  3. 把实测值写进断言
                                              ↓
                    5. 修完缺陷补回归  ←  4. 端到端验收（真实二进制）
```

**顺序不能倒。** 先量再定阈值，不能先拍一个阈值再去凑。

### 1. 探针（probe）必须是独立可执行文件

DSP 核心**不依赖宿主框架**（JUCE / M4L / 任何 GUI 运行时），单独编译成静态库，
探针只链接这个库。理由：只有能脱离宿主跑，才能做到毫秒级迭代、能进 CI、能写断言。

```bash
# 典型结构
core/        # DSP，零外部依赖
probe/       # 离线测量台，一个模块一个 main
tests/       # pytest 调探针、解析输出、断言
plugin/      # 宿主外壳，薄
```

探针输出用**机器可解析的键值格式**，一行一条：`名字 : 数值`。

> ⚠️ 解析正则的坑：名字部分禁止含 `=`，数值别写 `[\d.eE+-]+` 这种大杂烩。
> `=== engine_probe ===` 里的 `e` 会被当成科学计数法字符解析成数值。
> 名字用 `[A-Za-z_][A-Za-z0-9_ ]*`，数值用 `-?\d+(?:\.\d+)?(?:e[+-]?\d+)?`。

### 2. 量出基准值

同一组参数跑**至少两次**：一次目标配置，一次对照组。
对照组是区分度的唯一证据——没有对照组，0.9 和 0.001 你都不知道算好算坏。

### 3. 断言里写实测值

```python
# 实测：lag=切片长度处 0.9223，对照组（其他 lag）0.0022 —— 差 400 倍
assert ac == pytest.approx(0.92, abs=0.05), f"自相关 {ac}，预期 ~0.92"
assert ac > 20 * ac_control, "与对照组区分度不足"
```

注释里没写实测值的断言，下一轮就会被当成噪声删掉。

## 二、测量手法速查

| 想验证什么 | 怎么量 | 判据 |
|---|---|---|
| **周期性 / 重复 / 循环** | 在**预期 lag 处**取自相关，与其它 lag 处对比 | 目标 lag ≫ 对照组（本项目实测 0.92 vs 0.002） |
| **音高 / 定音** | Goertzel 在目标频率取能量；或数过零率 | 命中频率误差 ≤ 1 个样本对应值 |
| **亮度 / 频谱重心变化** | 分窗过零率序列 | 序列单调或起伏幅度符合设定 |
| **衰减 / 静音** | 分段 RMS | 各段单调递减，末段趋近设定值 |
| **回声位置 / 延迟时间** | 喂脉冲，找每次回声的**位置**与**幅度** | 间隔误差 < 1ms；反馈比误差 < 1% |
| **失真 / 谐波量** | 基频之外各次谐波的 Goertzel 能量之和 | 与对照组比倍数（折叠 1.30 vs 饱和 0.38） |
| **抖动 / 调制深度** | 短窗频率序列的极差 ÷ 中心频率 | 与设定百分比吻合（0.8 → ±4.00%） |
| **确定性 / 可复现** | 同参数渲染两次，逐样本比较 | 完全一致（所以随机数必须固定种子） |
| **稳定性 / 不自激** | 早段与晚段 RMS 之比 | 晚/早 ≤ 1.15（**不是"末段安静"**，见坑 1） |
| **旋钮单调性** | 扫参数，看指标序列 | 严格单调，无回折 |

## 三、五个真踩过的坑

### 坑 1：喂连续白噪声时，输出永远不会安静

**现象**：断言"末段 RMS < 1e-3"永远失败（实测 0.253）。
**根因**：输入本身是持续的白噪声，滤波器无论怎么振都会一直有输出。
**修法**：稳定性判据改成**稳态性** —— 晚段/早段 RMS 比。实测 0.9615~1.0013，全部 ≤ 1。
**推广**：定判据前先问"这个输入下，理论输出应该是什么形状"。别把"应该衰减"套在持续激励上。

### 坑 2：把调制乘在推进速率上 → 位置无界漂移

**现象**：wow/flutter 一开始正常，跑久了抖动变成**只往一边摆**。
**根因**：`pos += speed * (1 + wob)` 把抖动**积分**进了位置。漂移无界，撞到缓冲边界后被夹住，
抖动就被削成单侧。
**修法**：拆成两个量 ——
- `posAbs`：匀速位置，**只有它参与"缓冲区存量"计算**
- `wobOffset`：有界 LFO 位移（上限 3ms），读位置 = `posAbs - wobOffset`

**推广**：任何"加一点抖动"的需求，问一句"这个量会不会被积分"。会积分的一律改成有界偏移。

### 坑 3：只停读头，有限缓冲会把停住的播放"复活"

**现象**：变速模块速度拧到 0，前 8 秒安静（正确），第 8 秒后**自己响起来**。
单独跑模块却是精确 0。
**根因**：环形缓冲 8 秒。写头一直在 1x 前进，8 秒后绕回来**覆盖了读头正在读的位置**，
读头读到新素材，软限位又把速率拉回 1x。
**修法**：`stopping && tapeFull` 时**同时停住写头** + 停转时整段跳过软限位。
**验证**：停转 20 秒，末段 RMS 精确 0.00000000。

```cpp
const bool stopping = target <= kStopThreshold;   // 看目标值，不看平滑值
const bool tapeFull = lagPos >= maxLag_ - 1.0;    // 平滑值要 1 秒多才收敛，会漏判
if (!(stopping && tapeFull)) {
    ringL_[wAbs_ % cap_] = l[i];
    ++wAbs_;
}
```

**推广**：任何"暂停/冻结/停转"功能，只要缓冲是有限的，就必须问"写头会不会绕回来"。
真磁带停住读到的是**不变的静态磁化** —— 模拟这个行为就得冻结写头。

### 坑 4：参数显示名重复 → 端到端验收**静默跳过**

**现象**：端到端验收里打印 `!! 找不到参数: Stutter Size`，然后整段解构链验收一次都没跑，
最后还打印"通过"。
**根因**：新模块参数沿用了 `Size` / `Rate` / `Feedback` / `Tune` / `Speed`，
与既有参数撞名。宿主里按显示名查找会拿到第一个同名的。
**修法**：
1. 所有参数显示名加模块前缀（`Grain Size` / `Stutter Size` / `Tape Speed` / `Comb Tune`）。
   **内部 ID 不动**，状态存档不受影响。
2. 加一条静态回归测试：解析源码里的显示名字面量，断言**无重复**。
3. 端到端验收里按名查找失败必须**立即失败**，不许 `continue`。

**推广**：用户可见的列表（参数名、菜单项、枚举条目）必须唯一，而且要有一条机器检查盯着它。
"找不到就跳过"是最贵的 bug —— 它让你以为测过了。

### 坑 5：正则型测试匹配不到 → 循环体一次都不执行还显示绿

**现象**：排版测试"通过"了，但其实什么都没测。
**根因**：正则 `add(Knob|Toggle)\(([^;]*?)\);` 匹配到了**函数定义**
`void X::addKnob(const char* paramId, ...)`，解析出 `int x` 这种垃圾实参；
另一种情况是坐标写成符号常量 `kLabelY[n]` 而正则只认数字。
**修法**：
- 锚定到**字符串字面量开头**：`add(Knob|Toggle|Choice)\(\s*("[^"]*"(?:[^;]*?))\)\s*;`
- 匹配不到就 `assert len(items) >= N` 兜底，**不许 try/except 吞掉**

**推广**：**任何"遍历解析结果做检查"的测试，都必须先断言解析结果的数量下限。**
没有数量断言的解析型测试，本质上是一条 `pass`。

## 四、端到端验收：必须加载真实二进制

离线探针证明的是"算法写对了"，端到端证明的是"**这个文件能装进 DAW 干活**"。
两者不可互替 —— 参数布局、状态序列化、延迟上报、bypass 路径，只有真的当插件加载才暴露。

要点：
- 用宿主 SDK（如 `JUCE_PLUGINHOST_VST3`）写一个 console app，真的 `createPluginInstance` 再渲染
- **参数反解**：宿主里拿不到 `NormalisableRange`，且参数普遍带 skew（0.5 不是量程中点）。
  只能**二分 + `getText()` 回读**，约 48 次迭代反解出目标物理值，再断言回读值符合预期
- **参数总数**：框架会自动加一个 Bypass，所以断言 `size() >= 声明数 + 1`，别写等于
- 判定要覆盖：能加载 / 参数数对 / 峰值不越界 / 无 NaN·Inf / 各功能模块的指标 / 静音类功能真的到 0

## 五、汇报口径

- 先说结论（通过 / 不通过），再给数字
- 每个数字带上对照
- 沙箱拦截导致的"构建失败"要**核实清楚再报**：逐文件 sha256 比对 + `codesign -v`，
  确认二进制本体已更新，只是签名附属文件写不进去 —— 这种情况要如实说"签名文件没写成，
  二进制已同步"，不能含糊成"构建成功"
