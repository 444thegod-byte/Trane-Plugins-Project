# Träne Plug-ins Project

> 用于实验电子音乐制作与现场演出的**实时解构效果器**。
> 目标是做出 S280F、Fitness 那类解构俱乐部音乐里的声音：硬边切片、磁带停转、谐振染色、波形折叠。

**当前版本：v0.10.0** ｜ 格式：VST3 + AU + Standalone ｜ 通用二进制（`arm64` + `x86_64`）

---

## 一、这个项目是什么

Träne 是一个音频效果器插件，把输入音频捕获进缓冲区，然后可以无限冻结、粒子化成雾、
再逐级解构（切片重触发 → 谐振梳状 → 磁带变速 → 波形折叠 → 扫频 → 延迟 → 超大空间），
最后经过前瞻限制器输出。

它**不是**一个"综合效果器大礼包"，而是一条有明确顺序的解构链。顺序本身就是设计：

```
capture → freeze → grain → STUTTER → COMB → TAPE → ruin → sweep → delay → space → limiter
```

| 环节 | 作用 | 为什么在这个位置 |
|---|---|---|
| **freeze** | 把最近的输入变成无缝无限循环 | 解构的素材来源；不跟随 BPM，循环长度就是抓取区间长度 |
| **grain** | 带窗的重叠颗粒，把素材变成雾 | 提供"厚"的底子 |
| **STUTTER** | 硬边切片原地重触发 | 放在粒子之后：切的是"已经成雾的东西"，得到碎但厚。只做粒子会糊，只做切片会干 |
| **COMB** | 谐振梳状滤波，染上音高感 | 放在磁带之前：让谐振跟着磁带一起被拉慢，音高一起掉才像真的 |
| **TAPE** | 变速 + 磁带停转 + wow/flutter | 有限长度磁带机的物理行为，见下文 |
| **ruin** | 环形调制 → tanh 饱和 → **波形折叠** → 位深压碎 | 折叠在压碎之前：先折出谐波，再压位深把谐波糊开 |
| **sweep** | 随机扫频谐振滤波器 | 选随机而不是 LFO —— LFO 有周期感，随机没有 |
| **delay** | 阻尼延迟，可 ping-pong | |
| **space** | 超大空间混响 | |
| **limiter** | 前瞻峰值限制器 | 折叠和反馈都会爆电平，必须兜住 |

## 二、工程结构

```
vst/                      主工程（VST3 / JUCE）
├── core/                 DSP 核心。**刻意不依赖 JUCE**，可独立编译与离线渲染
├── probe/                离线测量台，一个模块一个 main()
├── plugin/               JUCE 外壳（Processor + Editor），很薄，只做接线
├── tests/                pytest，解析探针输出并断言
├── tools/                面板预览渲染等辅助脚本
├── external/JUCE/        第三方依赖（不进仓库，用 setup_juce.sh 拉取）
├── CMakeLists.txt
├── run_tests.sh          一键验证：构建 → pytest → 端到端验收
└── setup_juce.sh         拉取精确版本的 JUCE

src/                      Max for Live 版本（**已非主路线**，保留备查）
tools/                    M4L 构建工具
tests/                    M4L 静态验证
outputs/                  面板预览、需求报告
.workbuddy-ai/            项目记忆与配套技能
```

### 为什么 core 不依赖 JUCE

这是整个工程的硬性设计。只有 DSP 能**脱离宿主独立编译与离线渲染**，才谈得上
毫秒级迭代、自动化断言、数学检验。一旦 core 里出现 `#include <juce_*>`，
验证就只能靠"开 DAW 听"，这条路就废了。

### 为什么放弃 Max for Live

Max/MSP 依赖 iLok + Java，**无法在自动化环境启动**，只能静态验证接线。
代价是真实的：曾经一个功能连错两轮都没发现（根因是把 message 接进了 `record~`
的音频信号输入口）。VST3 能编译、能离线渲染、能用数学方法检验输出 ——
**可验证性**才是选它的真正理由，不是性能。

## 三、构建与验证

### 环境要求

- macOS + Xcode Command Line Tools
- CMake ≥ 3.22、Ninja
- Python 3.13 + `numpy`、`soundfile`

### 步骤

```bash
git clone <this-repo>
cd Trane-Plugins-Project/vst

./setup_juce.sh          # 拉取 JUCE 9.0.2（精确 commit，见脚本内注释）

./run_tests.sh           # 构建 + 全部测试 + 端到端验收
./run_tests.sh --quick   # 只跑测试，跳过构建
```

`run_tests.sh` 里的 Python 路径与 PATH 是按开发机写死的，**换机器要改成本机实际路径**：

```bash
PY=/Users/.../python
export PATH="/Users/.../bin:$PATH"
```

### 验收门槛

**构建 → pytest 82 项 → 端到端验收**，必须全过。

端到端验收这一步和前面的测试性质不同：它不是测 DSP 源码，而是把编译出来的
`.vst3` 真的当插件加载起来、通过 VST3 参数接口设参数、渲染音频、再分析结果。
它证明的是"**这个文件能装进 DAW 干活**"，而不只是"算法写对了"。

产物安装到 `~/Library/Audio/Plug-Ins/{VST3,Components}/`。

## 四、几个不显然但重要的实现约定

这些都是踩过坑之后定下来的，改之前先看 `.workbuddy-ai/memory/MEMORY.md`。

### 1. 停转必须同时停住写头

Tape 模块的缓冲区是有限的（8 秒）。如果只停读头、写头照常前进，
8 秒后写头会绕回来**覆盖读头正在读的位置**，停转就自己"复活"了。
真磁带停住时读到的是**不变的静态磁化** —— 模拟它就必须冻结写头。

实测证据：修复前停转末段 RMS 是 0.174（应该为 0）；修复后停转 20 秒仍精确为 0。

### 2. 调制不能乘在推进速率上

`pos += speed * (1 + wob)` 会把抖动**积分**成无界的位置漂移，撞到缓冲区边界后
被夹住，抖动就被削成"只往一边摆"。

正确做法是拆成两个量：`posAbs`（匀速位置，参与缓冲区存量计算）
+ `wobOffset`（有界 LFO 位移，上限 3ms）。

### 3. 前瞻限制器必须带前瞻

反馈式限制器对瞬态必然过冲（实测 +4.8 dB 时峰值 1.0062）。
前瞻 2ms + 单调队列最小增益，数学上不可能过冲。

代价是 2ms 延迟 → 必须 `setLatencySamples()`，并且**必须自己实现 `processBlockBypassed`**
（JUCE 基类版本假定延迟为 0，会把干声往前推）。

### 4. 参数显示名必须唯一

宿主按名字查找参数只认第一个。曾经三个参数都叫 `Size`、三个都叫 `Rate`，
结果是端到端验收里按名字找不到参数，**整段解构链验收静默跳过，最后还打印"通过"**。
现在有静态回归测试盯着显示名唯一性。内部 ID 可以随便改，显示名不行。

### 5. 随机数必须固定种子

粒子与扫频的随机数用固定种子的 xorshift32。否则渲染不可复现，无法做回归测试。

## 五、界面规范

目标：**Ableton Live 原生设备的平面化版本**，参考 Apple 的克制几何。

- 纯黑底；**只有黑白两色**，层次靠不透明度（主白 `1.00` / 标签 `0.84` / 线框 `0.48` / 盘面 `0.20`）
- 字体：运行时读取用户本机已安装 Ableton Live 12 里的
  `AbletonSans-Bold.otf`（标签、开关）与 `AbletonSansMedium-Regular.otf`（数值）。
  **不复制、不打包、不分发该字体**；找不到 Live 时降级 `Helvetica Neue Bold`。
- 旋钮 = 实心平面盘 + 1px 轮廓 + 起/中/止三刻度 + 高亮指针。
  **禁止**值弧、渐变、阴影、圆角卡片。
- 不显示产品名、功能介绍、运行状态等任何非交互文字。
- 面板 860 × 438，48 个参数 / 10 个分组。

界面规范详见 `.impeccable.md`；排版与视觉有 10 项静态回归测试盯着
（`vst/tests/test_editor_layout.py`），包括"每个参数都必须挂了界面控件"
—— 这条防的是"某个模块根本没有面板和旋钮"这类编译期和 DSP 测试都发现不了的问题。
