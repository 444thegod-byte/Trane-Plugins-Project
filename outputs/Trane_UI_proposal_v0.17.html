★ 这一版补齐了 12 个漏掉的控件
v0.16 定稿之后去对了一遍 createLayout()，发现设计稿只画了 36 个，插件里实际声明了 48 个。漏的 12 个是：6 个模块开关（grain_on / stutter_on / comb_on / tape_on / sweep_on / delay_on）、grain_position、grain_spray、delay_pingpong、ruin_mode、sweep_mode。这一版以那个函数为唯一依据重排。
对账
环位 41 个 + 边框开关 7 个 = 48 个 （createLayout 声明 48 个）✓
环位 = 真正的旋钮 / 档位；边框开关 = 模块的开关。两边的数量都写死在脚本里，改参数表时对账会立刻报错。
开关搬到圆的边框上
48 个控件平摊到 10 个圆，最挤的 GRAIN 有 9 个 —— 环位最多舒服地放 8 个。所以7 个模块开关不上环，改成圆的边框：关 = 淡黑细环，开 = 强调色红环。点圆心区（模块名）切换。这不只是省地方 —— 生命之树本来就是「光从 Keter 一级级流到 Malkuth」，开一个亮一个，整棵树逐级点亮。
边框亮不亮的规则
取决于「这个模块当前是否真的参与信号」：有 on 开关的 7 个看开关；RUIN 看 ruin_mode（mode = 0 就是纯干声，等于没开）；SPACE 看 space_mix；OUT 恒亮。
注意：createLayout() 里 6 个 _on 默认全是 false，freeze 也是 false。所以真正的初始状态是「只有 SPACE 和 OUT 亮」。本稿的演示状态是：FREEZE、GRAIN、SPACE、OUT。
档位参数怎么上环
sweep_mode 是 AudioParameterChoice（LP / BP / HP），也占一个环位：辐条长度 = 档位序号归一化（0 / 0.5 / 1.0），值直接写档位名。ruin_mode 是 0–1 的连续 morph（0 = Clear → 1 = Ruin），当普通旋钮处理。
简写对照
POS = Grain Position · SPRY = Grain Spray · PING = Delay PingPong · MODE = Ruin Mode · FB = Feedback · WOBB = Tape Wobble · CENT = Sweep Center · RESO = Sweep Reso · DIFF = Space Diffuse · SPRD = Grain Spread · DENS = Grain Density。
其余都是原词截断，不另列。宿主里的显示名不变，只是环上写简写。
文字改成环形排字
每个环位占圆周上一段，名与值都沿弧排、贴在自己那段刻度下（辐条落在段的中间）。名圈在外（半径 49.0 / 7.0px 大写 + 字距）、值圈在内（38.5 / 7.5px 等宽）—— 刻度在外，由外往内读正好是「SIZE 120ms」；反着放会读成「120ms SIZE」，参数名沦为补注。
环形文字的两条几何规则
① 方向按段选：SVG 里文字上方向 = 路径的左手法线。沿 +θ 走是径向朝外，沿 −θ 走是径向朝内。两种朝向的倾斜角恰好差 180°，所以每段取小的那个 —— 最大倾斜恒 ≤ 90°，永远不会倒立。② 下半圈半径 +0.5 字号：朝内时文字长在基线内侧，不补就会上下两半错开半个字。
段间空隙按弧长给
不按固定角度。固定角度的话 n 一变空隙就跟着变，可用弧长算不出来。现在固定 4px 弧长（按值圈半径折算），n=8 时值圈弧长 26.2px，最长的值「120ms」在 7.5px 等宽下约 22.1px —— 放得下。
每个节点的转盘都转过一下
段心默认从 12 点起算，但 n=2 / n=6 会正好把段摆在 3 点 / 9 点（那里倾斜 90°）。所以对每个节点搜一个旋转量，让最大倾斜最小（FREEZE → 0°、GRAIN → 60°）。平手时取离 0 最近的，结果唯一可复现。
准星也去掉了
红点删掉之后试过两版瞄准镜准星（十字臂 + 中心点 + 密位刻度），都被否了 —— 「好丑啊，算了不要准星了，我要文字在最中心就好了」。现在圆心只剩模块名，摆在正中心。
旋钮是辐条 · 长度就是值
每个环位是圆外的一条径向辐条，长度就是值（SPOKE_SPAN × v），末端一个小圆点。圆外那圈极淡的圆是标尺 —— 辐条的最大长度正好落在它上面。长度比角度直观，整圈长短不一，像日晷。
辐条长度是宿主里的真实位置
nrm() 复刻 JUCE NormalisableRange::convertTo0to1。这个函数早前是错的，已按源码修好：JUCE 是 pow(proportion, skew)（juce_NormalisableRange.h:147），不是 pow(proportion, 1/skew)。写反的后果很具体：grainSize 120ms 本该在 55.8% 处，错公式给出 2.6%。
柱距用回原图比例
文字在圆内，圆与圆之间不再需要留文字空间 —— 柱距就是原图的 2.932 倍（r/柱距 = 0.341），一点都不放宽。树宽高比 0.507，和原图一致。

字体与颜色
模块名与参数名 Inter Tight（紧凑，字距小），数值 IBM Plex Mono（等宽数字，改数值时不会跳）。白底 #FAFAF9 + 近黑 #0E0E0F，四档透明度分层。强调色 #8E1F1F 现在只有一个用途：亮着的模块边框。
